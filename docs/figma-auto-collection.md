# Figma 자동 수집 연동

업데이트: 2026-11-26

## 동작

- 최초 연결 코드와 현재 Figma 파일 URL로 연결합니다.
- 연결 정보를 Figma clientStorage에 저장하고, 플러그인을 다시 실행하면 resume API로 재연결합니다.
- 플러그인을 켜 둔 상태에서 변경된 노드를 모아 약 5초마다 전송합니다. 실패한 배치는 재시도합니다.
- 다시 실행하면 현재 상태를 비교합니다. 플러그인을 꺼 둔 동안의 개별 편집 이력까지 복원하지는 않습니다.
- FE는 약 5초마다 저장된 Figma 변경사항을 다시 조회하고 수집 상태와 최근 수신 시각을 표시합니다.
- 같은 배치의 재전송과 상태가 동일한 변경은 중복 활동을 만들지 않도록 처리합니다.
- 기존 snapshot API를 유지하며 Figma REST API로 전체 파일을 조회하는 방식으로 바꾸지 않았습니다.

## 연결 주소와 만료

배포용 플러그인은 https://fastapi-practice-jwse.onrender.com 을 사용합니다.
FE 배포 환경의 VITE_API_BASE_URL도 같은 주소로 설정합니다. 로컬 전용 환경변수 파일은 커밋하지 않습니다.

연결 토큰은 기존 백엔드 정책대로 발급 후 8시간 유효합니다. 활동으로 만료가 연장되지 않으며 만료되거나 연결을 해제하면 새 코드로 다시 연결해야 합니다. 새 연결 코드는 기존 연결을 대체합니다.

## 백엔드와 DB

resume, changes, snapshot API를 사용합니다. 운영 TiDB의 figma_plugin_connections에 nullable last_seen_at DATETIME, collection_state VARCHAR(24)가 추가된 것을 사용자 제공 결과로 확인했습니다. 행 수는 7건으로 보고되었습니다. 행 수 비교만으로 모든 기존 필드 값의 보존까지 검증한 것은 아닙니다.

2026-11-26 Render에 백엔드 커밋 241fd9ef20980ade685824296fbff67144892546 배포 완료를 확인했습니다. 운영 Swagger에 resume/changes/snapshot이 등록되었고 미인증 요청의 401 응답을 확인했습니다.

## 검증 범위

사용자가 로컬 FE·백엔드·Figma 플러그인의 변경 수집 동작을 확인했습니다. 운영 환경의 자동 재연결, 켜 둔 상태의 변경 수집, FE 표시, 중복 여부는 배포 후 실제 테스트 프로젝트로 확인해야 합니다. 프론트 브랜치 푸시만으로 운영 FE 적용이 완료되었다고 판단하지 않습니다.

플러그인 파일은 figma-plugin-local/code.js, ui.html, manifest.json입니다. 저장소를 업데이트해도 이미 설치한 플러그인이 자동 교체되지는 않으므로 사용하는 개발 플러그인 경로와 파일을 확인해야 합니다.
